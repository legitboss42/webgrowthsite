# Component Guidelines

## Goal

Future component work should move the repo toward a coherent platform UI, not a set of disconnected marketing sections.

## Reusable Components To Build Or Standardize Later

- platform hero
- Academy hub hero
- learning path rail
- tool card grid
- service card grid
- case study preview card
- founder trust block
- FAQ block
- article header block
- article sidebar / TOC
- related resources block
- newsletter / lead magnet signup block
- footer utility structure

## Hero Section Rules

- Hero must communicate page purpose quickly.
- One primary CTA.
- Optional secondary CTA only if it supports a clearly different next step.
- Avoid overloaded hero text.
- On homepage, hero should position the platform, not only sell a one-off offer.

## CTA Rules

- Primary CTA should match the page intent.
- Academy pages should avoid over-aggressive CTAs at the top.
- Service pages can be more direct.
- Utility pages should offer soft upgrade paths after value is delivered.

## Academy Cards

Should show:

- category / pillar
- title
- short usefulness statement
- read time
- optional freshness signal

Avoid decorative-only cards with no informational hierarchy.

## Tool Cards

Should show:

- what the tool does
- who it is for
- how long it takes to use
- whether it is free / gated / internal

## Service Cards

Should show:

- service name
- core outcome
- best-fit use case
- direct CTA

Do not make service cards vague.

## Testimonial / Proof Blocks

Proof blocks should prefer:

- case studies
- project summaries
- implementation screenshots
- clear deliverables

Avoid unverifiable praise walls.

## FAQ Components

- Use on service, Academy pillar, and conversion pages where they reduce friction.
- Visible FAQ content should be genuinely useful.
- Schema use should be deliberate, not automatic.

## Article Layout Components

Each long-form Academy article should eventually standardize:

- breadcrumb
- article header
- metadata row
- author/reviewer panel
- TOC
- structured content blocks
- related articles
- end CTA

## Breadcrumbs

- Use on Academy articles, service pages, and major subpages.
- Keep the hierarchy honest and simple.

## Table Of Contents

- Use on substantial long-form articles.
- Auto-generated from real headings where practical.
- Do not show a TOC for thin or short pages.

## Related Articles

- Must be relevance-driven, not random.
- Should support the same user journey or adjacent step.

## Newsletter / Lead Magnet Signup

When added or rebuilt later:

- should be useful, not intrusive
- should match the topic context
- should not interrupt the first reading experience too early

## Footer Structure

Future footer should prioritize:

1. platform summary
2. core navigation
3. Academy
4. free tools
5. services
6. trust/legal links
7. contact paths

Current issue to correct later:

- footer still links to campaign/noindex paths that should not sit in the core information architecture.
